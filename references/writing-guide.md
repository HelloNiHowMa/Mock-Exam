# 出題指引

這套練習簿的目標是檢查學員是不是**真的懂**，不是有沒有**看過**。好題目讓只看過教材的人選錯，想過的人選對。下面每條規則都是為了這個目標。

## 出題前：先列誤解，再寫題目

讀完教材後，先列出兩張清單，不要直接開始寫題目：

1. **關鍵概念**：教材裡真正要學員帶走的東西，通常 10 到 30 個。
2. **常見誤解**：每個概念旁邊寫下新手最可能搞錯的地方，例如名字相似但意思不同、「連上了」被當成「成功了」、把相鄰兩層的責任搞混。

誤解清單就是干擾選項和「容易卡住的地方」的來源。想不出誤解的概念，通常也出不出好題目，可以改成縮寫題或略過。

## 題型怎麼選

| 題型 | 適合考什麼 | 例子 |
|---|---|---|
| 單選 | 一個判斷：觀念辨識、情境排查、反事實推論、兩個說法誰對 | 「SCTP 已建立但收到 Setup Failure，先查什麼？」「假設把 F1AP 改放在 UDP 上，最直接失去什麼？」「同事 A 說…，同事 B 說…，誰對？」 |
| 複選 | 同一個判斷標準套到多個對象；「X 成立代表哪些事」 | 「下列哪些介面的封包會看到 SCTP 標頭？」 |
| 分類 | 依某個判斷依據分組；故意放名字相似但分類不同的項目 | 介面依承載方式分組；工作依負責節點分組 |
| 分類（帶標籤） | 流程依序經過哪幾站，並加入用不到的干擾項 | 下行資料從 UPF 到 UE 經過的介面（有兩個用不到） |
| 排序 | 流程先後、封包由外到內、協定堆疊 | UE 從開機到上網的程序順序 |
| 配對 | 一對一的對應關係 | 介面 ↔ 應用協定；現象 ↔ 排查方向 |
| 縮寫 | 把專有名詞記熟（輔助練習） | AMF → Access and Mobility Management Function |

使用者沒指定比例時，建議單選約一半，複選和分類各 15% 到 20%，排序和配對合計 10% 到 15%。教材裡縮寫很多時再加縮寫題。

情境題和排查題最能分出「懂」和「看過」，單選題裡至少三分之一用情境開頭：給 log、現象、或同事的說法，再問判斷。

## 干擾選項

- **每個錯誤選項都對應一個真實的誤解**，不寫明顯錯誤、沒人會選的選項。
- **正確答案不要是最長、最精確的那個。** 這是 AI 出題最常見的毛病：正確選項寫得完整具體，干擾選項寫得短又含糊，學員挑最長的就猜對了。把干擾選項寫得一樣具體，有時讓某個干擾選項最長，有時讓正確答案最短。`build.py` 會檢查這一點。
- 不用「以上皆是」「以上皆非」。
- 「一定」「永遠」「完全不」這類絕對詞是洩題線索，只在它本身就是考點時使用。
- 選項之間不要互相包含，也不要有兩個意思一樣的選項。
- 選項順序不用刻意安排。練習、模擬考和列印時選項都會打亂，資料裡答案放在第幾個都可以。分類題的項目也一樣，照分組順序寫沒關係。

## 題幹

- 一題只考一個概念。
- 情境要具體：寫出設備、訊息名稱、log 內容，不要只寫「發生錯誤時」。
- 題幹的關鍵字不要只出現在正確選項裡，否則學員可以靠比對文字猜答案。
- 少用否定題。真的要用時，寫成「下列何者『不』正確」。
- 複選題註明「（選出所有正確答案）」。分類題有干擾項時，註明「有 N 個項目用不到」。

## 解析

每題都要有解析，固定兩段，中間用 `\n` 分開：

1. **說明**：為什麼正確答案對，主要的干擾選項各錯在哪裡。用學員的語言講，不要只重述答案。
2. **容易卡住的地方**：以「容易卡住的地方：」開頭，點出這題針對的誤解，並給一個以後遇到類似問題可以用的判斷方法。

範例：

> SCTP 已連上，表示路由和防火牆大致沒問題，傳輸層可以先排除。Setup 被拒是應用層設定不相容，Failure 訊息裡的 cause 值就是 F1AP 告訴你的原因……
> 容易卡住的地方：一看到「連線失敗」就去查網路，是最常見的反射動作。先判斷失敗發生在哪一層，才知道該查網路還是查設定。

整段大約 100 到 250 字。不要用 Markdown 語法，頁面會原樣顯示星號和井號。

### 逐選項解析（oe）

選項各錯在不同的誤解，一段解析講不清楚時，單選、複選題可以再加 `oe`，逐一說明每個選項（格式見 `schema.md` 2.8）。適合：

- 四個選項都很像，學員選錯時最想知道「我選的那個錯在哪」。
- 計算題、判斷題，每個錯誤選項代表一種算錯或想錯的方式。

寫法：

- 照 `o` 的原始順序寫，一個選項一兩句：對的講為什麼對，錯的講錯在哪個誤解，不要只寫「錯誤」。
- 選項會打亂，**不要寫 A、B、C 或「第幾個選項」**；要提到別的選項時，引用它的內容。
- 有 `oe` 時，`e` 改成講整題的判斷方法和容易卡住的地方，不要再把每個選項講一遍。
- 不需要說明的選項寫 `""`。

## 易混淆題組

把考相似概念的 2 到 4 題綁成一組，練習時連續出現，學員比較容易看出差別。每組寫一兩句「分辨關鍵」，講怎麼區分，不要只是重述概念。一份練習簿 2 到 7 組就夠了。

## 情境題組

教材是個案、情境或一段系統說明，同一段背景要出好幾題時，用情境題組（格式見 `schema.md` 第 5 節）：情境文字寫一次，題目只寫這一題要問的事。作答時情境一直顯示在題目上方。

什麼時候用：

- 同一段背景出兩題以上。
- 背景超過兩三句。在每題的 `q` 裡重複交代會讓題目變長，也不像真正的考試。

只有一題、或背景一兩句話就講完時，直接寫在題目裡就好。

寫法：

- `text` 寫所有題目都需要的背景：系統、角色、拓撲、現象、log。只和某一題有關的條件寫在那一題的 `q`。
- 題目的 `q` 不要重述情境，用「情境裡的……」「依情境……」指回去。
- `qs` 照作答的順序排：先問看了情境就能回答的，再問需要推論的。
- 情境文字不要超過 800 字，太長時刪掉和題目無關的背景，或拆成幾個情境題組。手機上一個畫面大約只放得下 200 到 250 字。
- 情境提到「如圖」時，用 `img` 附圖。
- 同一組的題目放在同一章。

避免同一組互相洩題。同一組的題目會連續出現，作答後馬上看得到選項、答案和解析，所以前一題不能讓下一題變簡單：

- 前一題的選項或答案不能透露下一題的答案。例如第一題問「每則訊息走哪個介面」，第二題的排序項目就只寫訊息名稱，不要寫成「N2：AMF 送出……」。
- 前一題的解析不要提前講下一題的考點。寫完一組後，照 `qs` 的順序把每題的解析讀一遍，問自己：看完這段，下一題是不是變成送分題？
- 情境文字本身不要直接寫出某一題的答案。題目要考的是從情境推論，不是從情境抄。
- 作答的人關掉「整組出」時，同一組的題目可能不照順序出現；後面題目的題幹和選項，同樣不要洩漏前面題目的答案。

## 題幹裡的表格和圖（blk）

題目本身要給一張表、一段需求、一段 log 或程式碼時，用題幹區塊 `blk`（格式見 `schema.md` 2.7），不要把表格硬寫成一行一行的文字，也不要截圖。

| 題目裡要給的東西 | 用什麼 |
|---|---|
| 表格（決策表、狀態轉換表、測試結果） | `blk` 的 `table`：文字可以選取、放大不會糊，深色模式和列印都清楚，AI 解析也讀得到每一格 |
| 一段引述的需求、user story、同事的說法 | `blk` 的 `box` |
| log、指令輸出、程式碼、虛擬碼 | `blk` 的 `pre`：等寬字，空白對齊不會跑掉 |
| 狀態圖、流程圖、拓撲這類白底黑線的圖，而且要夾在題目文字中間 | `blk` 的 `img`，寫好 `alt` 和顯示寬度 `w`；深色模式會反相 |
| 簡單的長條圖、示意圖，自己用 SVG 畫 | `blk` 的 `svg`，線和字用 `currentColor`，寫好 `alt` |
| 照片、彩色截圖、要挖空關鍵字的架構圖，放在題目文字後面就好 | 題目附圖 `img`（解析用的完整版放 `eimg`），見下一節 |
| 選項本身是表或圖 | 選項圖片 `oimg`，見下一節 |

- 表格的格子只放短文字，長的說明寫在題目文字裡。表頭用 `hr`、列標題用 `hc` 標出來，螢幕報讀才念得對。
- `img` 和 `svg` 的 `alt` 寫出圖裡答題需要的資訊（例如每個轉換的起點、事件和終點）。SVG 不會送給 AI，AI 看不到圖時只能靠 `alt`。
- 一題只放答題需要的區塊；區塊太大時（手機上要捲兩個畫面以上），考慮拆成情境題組。

## 圖片

- AI 不能畫圖，只能引用使用者提供的圖檔。題目要用到圖時，先看過圖片內容再出題，代號用圖檔名稱（去掉副檔名）。
- 有架構圖時，常見做法是準備兩張：題目圖把關鍵字挖空（例如黃色問號），解析圖是完整版，分別放在 `img` 和 `eimg`。
- 題目或解析寫了「圖上」「如圖」時，一定要附圖。
- 選項本身是圖或表格、用文字講不清楚時（例如考「哪一張決策表正確」），用 `oimg` 放選項圖片，`o` 寫成看得出是哪一張、但不洩漏答案的簡短說明。只是圖裡的一兩個詞，就直接寫成文字選項。
- 同一題的選項圖片用同一個畫布寬度輸出（取最寬那張的寬度，其他靠左補白），圖裡的字至少是畫布寬度的 1/20，手機縮小後字級才一致、看得清楚。圖裡不要畫 A、B、C，選項會打亂。

## 正確性與來源

- 只根據使用者提供的教材出題。教材沒寫、或你不確定的內容，不要出。
- 不要捏造規格編號、章節號、指令參數。引用時要和教材一致。
- 答案有爭議時，加上 `"flag": true`，並在解析說明爭議在哪裡。
- 練習簿會分享給別人。不要把考古題、原廠題庫或商業題庫的原文搬進來；可以用自己的話考同一個概念。

## 語言

- 繁體中文、台灣用語，全形標點。
- 協定、指令、訊息與參數名稱保留英文原文。
- 同一個名詞全份統一寫法，例如不要一下寫「CU-CP」一下寫「CUCP」。

## 交出前自我檢查

- [ ] 每題都能對應到教材裡的某一段。
- [ ] 每個干擾選項都有一個對應的誤解。
- [ ] 正確答案沒有系統性地最長或最精確。
- [ ] 至少三分之一的單選題是情境題或排查題。
- [ ] 每題解析都有「容易卡住的地方」。
- [ ] 有 `oe` 的題目照 `o` 的原始順序寫，裡面沒有 A、B、C 或「第幾個選項」。
- [ ] 題目裡的表格、log 用 `blk`，`{{0}}` 的位置和區塊數對得上；圖片區塊和 SVG 都有 `alt`。
- [ ] 情境題組照 `qs` 的順序讀過一遍：前一題的選項、答案和解析沒有讓下一題變簡單。
- [ ] 題號從 1 開始連續、沒有重複；縮寫題沒有重複。
- [ ] 跑過 `build.py`，沒有錯誤，品質提醒都處理過或有理由保留。
