# 題庫格式說明

練習簿是一個 HTML 檔。檔案最上方有兩個資料區塊，換題庫只要改這兩塊，下面的程式（引擎）不用動：

```html
<script type="application/json" id="bank">
{ "config": {...}, "questions": [...], "abbr": [...], "groups": [...] }
</script>
<script type="application/json" id="bank-images">
{ "圖片代號": "data:image/png;base64,..." }
</script>
```

目錄：

1. config：練習簿設定
2. questions：五種題型（單選、複選、分類、排序、配對）
3. abbr：縮寫題
4. groups：易混淆題組
5. 圖片
6. 會讓頁面報錯的格式規則

---

## 1. config：練習簿設定

```json
{
  "id": "fw-upgrade-101",
  "title": "韌體升級流程練習簿",
  "subtitle": "給新進 RD 的自我檢查。",
  "mainLabel": "觀念題",
  "passLine": 80,
  "passNote": "",
  "pace": 60,
  "examNote": "",
  "aiRole": "韌體升級流程的內訓講師",
  "aiTerms": "指令、參數與錯誤碼保留英文原文",
  "aiBasis": "依公司的韌體升級 SOP 與產品規格說明，著重「哪個步驟、哪個元件、失敗時看哪個 log」",
  "abbrScope": "韌體升級流程"
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | 2 到 40 個小寫英文、數字或連字號。用來分開每份練習簿的作答紀錄，**發佈後不要改**，改了紀錄就接不回來。 |
| `title` | 是 | 頁面標題。結尾的「練習簿」會在列印時自動去掉。 |
| `subtitle` | | 標題下的一句說明：給誰用、想檢查什麼。 |
| `mainLabel` | | 選擇題在介面上的名稱，預設「選擇題」。 |
| `passLine` | | 模擬考的參考及格線（%），預設 80。 |
| `passNote` | | 及格線旁的補充，例如「原廠不公布及格分數，這是常見參考值」。 |
| `pace` | | 模擬考倒計時每題幾秒，預設 60。 |
| `examNote` | | 倒計時設定下方的說明，例如「正式考試是 50 題、120 分鐘，平均每題 144 秒。」沒填時顯示預設每題秒數。 |
| `aiRole` | | 「AI 解析」按鈕的講師角色，接在「你是」後面。 |
| `aiTerms` | | 哪些名詞保留英文。 |
| `aiBasis` | | AI 解析要依據什麼、著重什麼。寫出具體的規格或文件名稱，解析會準很多。 |
| `abbrScope` | | 縮寫題 AI 說明的領域，接在「在」後面、「中會出現在什麼情境」前面。 |
| `storageKeys` | | 進階：沿用舊練習簿的作答紀錄時才需要，平常不要填。 |

AI 解析按鈕只有在 Claude 發佈的 artifact 裡才會出現；放到其他平台時自動隱藏，不影響作答。

引擎送給 AI 的提示詞，除了上面這幾個欄位，還固定帶兩條規則（題庫解析頁和補充題表單的「請 AI 幫忙寫」都一樣）：

- 選擇題的選項不標 A、B、C，也不編號，而是照題庫順序列成清單，每行行尾標出題庫的判定（`〔題庫標示：正確〕`／`〔題庫標示：不正確〕`），並要求 AI 直接引用選項內容。作答時選項順序是打亂的，解析裡出現代號或「第幾個選項」會對到別的選項。題庫的解析 `e` 也一樣，不要用代號或序號稱呼選項。
- 教材或題庫解析沒有寫到、AI 自己加上的內容，要明講是補充，不能寫成教材的說法；沒有加就不提補充。

## 2. questions：題目

每題都有的欄位：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `n` | 是 | 題號，整數，不能重複。1 到 999 是題庫；1001 到 9998 是頁面內建的補充題（見 2.6）；1000 不能用。**作答紀錄綁在題號上**，發佈後不要重新編號；刪題就讓那個號碼空著，新題接在同一區最大號後面。 |
| `type` | | `mcq`（單選，可省略）、`multi`、`cls`、`order`、`match`。 |
| `q` | 單選、複選、分類必填 | 題目文字。 |
| `e` | 建議 | 解析。用 `\n` 分段，第二段以「容易卡住的地方：」開頭。 |
| `img` | | 題目附圖的代號陣列，例如 `["topo1"]`。 |
| `eimg` | | 作答後才顯示的解析附圖。常見用法：`img` 是關鍵字挖空的版本，`eimg` 是完整版。 |
| `flag` | | `true` 表示爭議題：題庫地圖的題號格會加上紫色「!」和加粗外框，圖例顯示爭議題數，列印時也會標註。爭議的地方寫在解析裡。 |

練習和模擬考時，選項、排序項目和配對右欄都會自動打亂，資料裡照正確答案的順序寫就好。

### 2.1 單選（mcq）

```json
{"n": 1, "q": "DU 的 log 顯示 SCTP 已建立，但接著收到 F1 Setup Failure。最合理的排查方向是？",
 "o": ["檢查 CU 與 DU 之間的 IP 路由和防火牆", "檢查 RU 的 eCPRI 設定", "改用 UDP 重新建立 F1-C 連線", "看 Failure 的 cause，比對兩端的 PLMN 與 NR CGI 設定"],
 "a": 3,
 "e": "SCTP 已連上，路由和防火牆可以先排除……\n容易卡住的地方：一看到「連線失敗」就去查網路……"}
```

- `o`：2 到 6 個選項，不能重複。
- `a`：正確選項的位置，**從 0 開始**（0 是第一個）。

### 2.2 複選（multi）

```json
{"n": 4, "type": "multi", "q": "下列哪些介面的封包裡會看到 SCTP 標頭？（選出所有正確答案）",
 "o": ["N3", "Open Fronthaul 的 C-plane", "F1-U", "E1", "F1-C", "N2"],
 "a": [3, 4, 5], "e": "……"}
```

- `a`：正確選項位置的陣列。全對才算答對。
- 題目註明「（選出所有正確答案）」。

### 2.3 分類（cls）

學員先點項目、再點格子，把項目放進各組。可以有用不到的干擾項目。

```json
{"n": 7, "type": "cls", "q": "把每個介面放到它所使用的承載方式底下。",
 "items": ["F1-U", "Open Fronthaul C-plane", "N2", "E1", "N3", "Open Fronthaul U-plane", "F1-C"],
 "groups": [
   {"t": "AP／SCTP／IP",   "s": [{"a": 2}, {"a": 3}, {"a": 6}]},
   {"t": "GTP-U／UDP／IP", "s": [{"a": 4}, {"a": 0}]},
   {"t": "eCPRI／Ethernet", "s": [{"a": 1}, {"a": 5}]}
 ], "e": "……"}
```

- `items`：所有項目（含干擾項），不能重複。
- `groups`：每組有標題 `t` 和格子 `s`。每格的 `a` 是該放的項目在 `items` 裡的位置（從 0 開始）。
- 格子沒有標籤時，同一組裡順序不拘。
- 格子加上標籤 `l`，就變成逐格判分。適合「依序經過哪幾站」這類題目：

```json
"groups": [{"t": "由 UPF 往 UE 的順序", "s": [
  {"l": "第 1 站", "a": 3}, {"l": "第 2 站", "a": 5}, {"l": "第 3 站", "a": 0}
]}]
```

- 每個項目最多放進一格。沒放進任何格子的項目就是干擾項，題目要註明「有 N 個項目用不到」。

### 2.4 排序（order）

```json
{"n": 10, "type": "order", "q": "UE 從開機到可以上網，把下列程序排成正確的先後順序。",
 "items": ["RRC Setup：……", "Registration：……", "PDU Session Establishment：……", "使用者資料開始經 N3 傳送"],
 "e": "……"}
```

- `items` 照**正確順序**寫，至少 2 個，不能重複。
- 需要干擾項時，改用帶標籤的分類題。

### 2.5 配對（match）

```json
{"n": 13, "type": "match", "q": "把每個介面對到它使用的應用層協定。",
 "pairs": [["N2", "NGAP"], ["E1", "E1AP"], ["F1-C", "F1AP"], ["Xn-C", "XnAP"]],
 "e": "……"}
```

- `pairs`：至少 2 組 `[左, 右]`。左欄固定，右欄練習時會打亂。
- 左欄、右欄各自都不能重複，否則無法判定。

### 2.6 頁面內建的補充題（題號 1001 以上）

題號寫成 1000 + k（k 從 1 開始）的題目算補充題，題型和欄位跟題庫的題目完全一樣。用在題庫定稿之後才加的題目，讓題庫原本的題號和統計不受影響。

- 題庫地圖上不放在「題庫」區，而是依題型排進補充題區：單選、複選在「補充題：選擇題」，分類、排序、配對在「補充題：拖拉題」。
- 各區自己從 1 編號，依 k 的先後排，所以畫面上的號碼和 k 不同。例如 1001（單選）、1002（排序）、1003（複選）會顯示成補充選擇題第 1 題、補充拖拉題第 1 題、補充選擇題第 2 題。
- 有補充題時，練習設定會出現「題目來源」，可以選「只出題庫」或「只出補充題」。統計的「題庫」列只算 1 到 999 的題目。
- 使用者在頁面上自己新增的補充題，編號接在最大的 k 之後，和內建補充題排在同一區。
- 已經發佈的練習簿要再加內建補充題時，k 要接在頁面裡的補充題和帳號裡的補充題（作答紀錄的 `extras`）兩邊最大的號碼後面。k 如果比使用者已經新增的補充題小，畫面上的號碼會重排；作答紀錄綁在題號上，不受影響。

## 3. abbr：縮寫題

學員看到縮寫，要寫出英文全名。判定時會忽略大小寫、標點、連字號、多餘空白、and／of／the 這類虛詞和字尾的複數 s。

```json
"abbr": [
  {"cat": "介面協定", "abbr": "GTP-U", "full": "GPRS Tunnelling Protocol User Plane",
   "alts": ["GPRS Tunneling Protocol User Plane"],
   "e": "封裝使用者資料的隧道協定，跑在 UDP 上……"}
]
```

- `cat`：分類，練習時顯示。
- `alts`：其他也算對的寫法（拼法差異、常見變體），最多 10 個。
- 作答紀錄依**排列位置**記錄。新增加在最後，不要插入或刪除中間的項目。

## 4. groups：易混淆題組

把考相似概念、容易搞混的題目綁成一組。練習時同組連續出題，每題作答後附上這組的「分辨關鍵」。

```json
"groups": [
  {"name": "通道通了 vs 合作成功", "qs": [3, 5, 15],
   "key": "SCTP association 是通道，Setup 是應用層合作。控制面全部成功，也不代表使用者面的路徑是通的。"}
]
```

- `qs`：至少兩個存在的題號，可以跨題型。
- `key`：一兩句話講清楚怎麼分辨。

## 5. 圖片

圖片區塊是 `{"代號": "圖片"}`。題目用 `img`／`eimg` 引用代號。值可以是：

- data URI：`"data:image/png;base64,..."`。圖片包在 HTML 裡，單一檔案就能分享。**放到 Claude artifact 時一定要用這種。**
- 相對路徑或網址：`"images/topo1.png"`。HTML 放在內部網站、圖片放在旁邊的資料夾時可以用，檔案比較小。

用 `scripts/build.py --images 資料夾` 時，檔名去掉副檔名就是代號，PNG／JPG 會自動轉成 WebP 縮小。

AI 解析會把題目附圖一起給 AI 看，但只限內嵌的 PNG、JPG、GIF、WebP；SVG 和外部檔案不會送。

## 6. 會讓頁面報錯的格式規則

頁面開啟時會檢查格式，有錯的題目不會出現在練習裡，錯誤列在頁面最上方。最常見的錯：

- JSON 語法：最後一個項目後面多了逗號、字串裡的雙引號沒有寫成 `\"`、用了全形引號。
- `a` 從 1 開始算。正確是從 0 開始。
- 題號 `n` 重複，或用了 1000。
- 分類題的同一個項目放進兩格。
- 配對題右欄有重複的字。
- 兩個區塊裡出現 `</script` 這幾個字（會讓瀏覽器提早結束區塊）。
