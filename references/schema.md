# 題庫格式說明

練習簿是一個 HTML 檔。檔案最上方有兩個資料區塊，換題庫只要改這兩塊，下面的程式（引擎）不用動：

```html
<script type="application/json" id="bank">
{ "config": {...}, "questions": [...], "abbr": [...], "groups": [...], "cases": [...], "chapters": [...], "sets": [...] }
</script>
<script type="application/json" id="bank-images">
{ "圖片代號": "data:image/png;base64,..." }
</script>
```

目錄：

1. config：練習簿設定
2. questions：五種題型（單選、複選、分類、排序、配對）
3. abbr：縮寫題
4. groups：易混淆題組
5. cases：情境題組
6. chapters：章節（依章節出題）
7. sets：卷別與整套模擬考
8. 不可作答的題目（`void`）
9. 圖片
10. 會讓頁面報錯的格式規則

---

## 1. config：練習簿設定

```json
{
  "id": "fw-upgrade-101",
  "title": "韌體升級流程練習簿",
  "subtitle": "給新進 RD 的自我檢查。",
  "mainLabel": "觀念題",
  "passLine": 80,
  "passNote": "",
  "pace": 60,
  "examNote": "",
  "aiRole": "韌體升級流程的內訓講師",
  "aiTerms": "指令、參數與錯誤碼保留英文原文",
  "aiBasis": "依公司的韌體升級 SOP 與產品規格說明，著重「哪個步驟、哪個元件、失敗時看哪個 log」",
  "abbrScope": "韌體升級流程"
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | 2 到 40 個小寫英文、數字或連字號。用來分開每份練習簿的作答紀錄，**發佈後不要改**，改了紀錄就接不回來。 |
| `title` | 是 | 頁面標題。結尾的「練習簿」會在列印時自動去掉。 |
| `subtitle` | | 標題下的一句說明：給誰用、想檢查什麼。 |
| `mainLabel` | | 主要題型在練習設定「題型」裡的名稱，例如「觀念題」，預設「選擇題」。主要題型包含所有非縮寫題（單選、複選、分類、排序、配對），不分題庫或補充題；另外還有「縮寫題」「拖拉題」（只有分類、排序、配對）和「全部題型」。作答的人選的題型會記住，每日一題和考我一題也照這個題型出題。 |
| `passLine` | | 模擬考的參考及格線（%），預設 80。整套模擬考也用這條線。 |
| `passNote` | | 及格線旁的補充，例如「原廠不公布及格分數，這是常見參考值」。 |
| `passCount` | | `true` 時，模擬考成績頁在及格線後面寫出「這回要答對 N 題」，及不及格也照題數判斷。整套模擬考一律會寫。 |
| `pace` | | 模擬考倒計時每題幾秒，預設 60。 |
| `extraTime` | | 非母語加時的比例，大於 0、最多 1，例如 `0.25` 代表多 25%。填了之後，倒計時的「每題時間」多一個 `pace` 乘上 1 + `extraTime` 的選項（例如 90 秒變 112.5 秒），整套模擬考也多一個加時後的考試時間（60 分鐘變 75 分鐘）。沒填就沒有這兩個選項。 |
| `examNote` | | 倒計時設定下方的說明，例如「正式考試是 50 題、120 分鐘，平均每題 144 秒。」沒填時顯示預設每題秒數。 |
| `multiCount` | | `true` 時，題庫的複選題提示寫出要選幾個（「選出 2 個答案」），練習、模擬考和列印都一樣。正式考試會告訴考生選幾個時再開。頁面上新增的補充題不受影響。 |
| `setLabels`、`fullMinutes`、`fullNote` | | 卷別和整套模擬考的設定，題庫有 `sets` 時才用得到，見第 7 節。 |
| `notice` | | 主頁最下方的說明，例如題目的來源和著作權。用 `\n` 分段。 |
| `printNotice` | | 列印出來的最後一行說明，例如題目的著作權。 |
| `printNoticeUnoff` | | 列印的題目裡有原創題（`unoff`）時，接在 `printNotice` 後面的說明，例如「E 卷是另行編寫的原創練習題」。 |
| `aiRole` | | 「AI 解析」按鈕的講師角色，接在「你是」後面。 |
| `aiTerms` | | 哪些名詞保留英文。 |
| `aiBasis` | | AI 解析要依據什麼、著重什麼。寫出具體的規格或文件名稱，解析會準很多。 |
| `abbrScope` | | 縮寫題 AI 說明的領域，接在「在」後面、「中會出現在什麼情境」前面。 |
| `storageKeys` | | 進階：沿用舊練習簿的作答紀錄時才需要，平常不要填。 |

AI 解析按鈕只有在 Claude 發佈的 artifact 裡才會出現；放到其他平台時自動隱藏，不影響作答。

引擎送給 AI 的提示詞，除了上面這幾個欄位，還固定帶兩條規則（題庫解析頁和補充題表單的「請 AI 幫忙寫」都一樣）：

- 選擇題的選項不標 A、B、C，也不編號，而是照題庫順序列成清單，每行行尾標出題庫的判定（`〔題庫標示：正確〕`／`〔題庫標示：不正確〕`），並要求 AI 直接引用選項內容。作答時選項順序是打亂的，解析裡出現代號或「第幾個選項」會對到別的選項。題庫的解析 `e` 也一樣，不要用代號或序號稱呼選項。
- 教材或題庫解析沒有寫到、AI 自己加上的內容，要明講是補充，不能寫成教材的說法；沒有加就不提補充。

## 2. questions：題目

每題都有的欄位：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `n` | 是 | 題號，整數，不能重複。1 到 999 是題庫；1001 到 9998 是頁面內建的補充題（見 2.6）；1000 不能用。**作答紀錄綁在題號上**，發佈後不要重新編號；刪題就讓那個號碼空著，新題接在同一區最大號後面。 |
| `type` | | `mcq`（單選，可省略）、`multi`、`cls`、`order`、`match`。 |
| `q` | 單選、複選、分類必填 | 題目文字。 |
| `e` | 建議 | 解析。用 `\n` 分段，第二段以「容易卡住的地方：」開頭。 |
| `img` | | 題目附圖的代號陣列，例如 `["topo1"]`。 |
| `eimg` | | 作答後才顯示的解析附圖。常見用法：`img` 是關鍵字挖空的版本，`eimg` 是完整版。 |
| `oimg` | | 只用在單選、複選：每個選項的圖片代號，和 `o` 一樣長，沒有圖的選項寫 `null`。選項本身是圖或表格時才用，見 2.1 和第 9 節。 |
| `ch` | | 這題屬於哪一章，寫 `chapters` 裡那一章的 `id`。教材有分章節時才用，見第 6 節。 |
| `blk` | | 題幹裡的表格、方框、程式碼或圖，題目文字 `q` 用 `{{0}}`、`{{1}}` 標出位置。見 2.7。 |
| `oe` | | 只用在單選、複選：逐一說明每個選項，和 `o` 一樣長。見 2.8。 |
| `lo`、`k`、`ref` | | 學習目標、認知層級（例如 K2）、出處。顯示在解析下方。見 2.9。 |
| `set`、`no`、`add`、`unoff` | | 卷別、卷內題號、附加題、原創題。題庫有 `sets` 時才用，見第 7 節。 |
| `flag` | | `true` 表示爭議題：題庫地圖的題號格會加上紫色「!」和加粗外框，圖例顯示爭議題數，列印時也會標註。爭議的地方寫在解析裡。 |
| `void` | | `true` 表示不可作答：題目有問題，留在題庫裡但不出題、不計分。省略或 `false` 就是一般題目。用法見第 8 節。 |
| `voidNote` | 有 `void` 時建議 | 這題哪裡有問題，會顯示給作答的人看。 |

題目屬於哪個情境題組，寫在 `cases` 的 `qs` 裡，題目本身不用加欄位，見第 5 節。

練習和模擬考時，選項、排序項目、配對右欄和分類題的項目都會自動打亂，資料裡照正確答案的順序寫就好。列印時單選、複選和分類題的選項也會固定打亂（同一題每次印出來的順序相同），答案表跟著換成印出來的字母。

### 2.1 單選（mcq）

```json
{"n": 1, "q": "DU 的 log 顯示 SCTP 已建立，但接著收到 F1 Setup Failure。最合理的排查方向是？",
 "o": ["檢查 CU 與 DU 之間的 IP 路由和防火牆", "檢查 RU 的 eCPRI 設定", "改用 UDP 重新建立 F1-C 連線", "看 Failure 的 cause，比對兩端的 PLMN 與 NR CGI 設定"],
 "a": 3,
 "e": "SCTP 已連上，路由和防火牆可以先排除……\n容易卡住的地方：一看到「連線失敗」就去查網路……"}
```

- `o`：2 到 6 個選項，不能重複。
- `a`：正確選項的位置，**從 0 開始**（0 是第一個）。

選項本身是圖或表格（例如四張決策表選一張），文字講不清楚時，加上 `oimg`：

```json
{"n": 21, "q": "依下列規則，哪一張決策表正確？",
 "o": ["表 1：兩個 input 欄、一個 output 欄", "表 2：一個 input 欄、一個 output 欄",
       "表 3：三個 input 欄、一個 output 欄", "表 4：兩個 input 欄、兩個 output 欄"],
 "oimg": ["dmn-t1", "dmn-t2", "dmn-t3", "dmn-t4"],
 "a": 0, "e": "……"}
```

- `oimg`：和 `o` 一樣長的陣列，每格是圖片代號，或 `null`（那個選項沒有圖）。圖片顯示在選項文字下方。
- `o` 仍然必填，寫成圖片的簡短說明，一樣不能重複。誤選分析、列印的答案表、螢幕報讀和 AI 解析都只看得到這段文字，要寫到看得出是哪一張，但不要洩漏答案。
- 選項會打亂，圖片跟著選項走。**圖裡不要畫 A、B、C 這類代號**，畫面上的字母和圖裡的對不上。
- 同一題的選項圖片要用同一個畫布寬度輸出，見第 9 節「選項圖片」。

### 2.2 複選（multi）

```json
{"n": 4, "type": "multi", "q": "下列哪些介面的封包裡會看到 SCTP 標頭？（選出所有正確答案）",
 "o": ["N3", "Open Fronthaul 的 C-plane", "F1-U", "E1", "F1-C", "N2"],
 "a": [3, 4, 5], "e": "……"}
```

- `a`：正確選項位置的陣列。全對才算答對。
- 題目註明「（選出所有正確答案）」。
- 選項是圖時一樣用 `oimg`，規則和單選相同。例如四個選項的題目寫 `"oimg": ["dmn-t1", "dmn-t2", "dmn-t3", null]`：前三個選項是表，第四個只有文字。

### 2.3 分類（cls）

學員先點項目、再點格子，把項目放進各組。可以有用不到的干擾項目。

```json
{"n": 7, "type": "cls", "q": "把每個介面放到它所使用的承載方式底下。",
 "items": ["F1-U", "Open Fronthaul C-plane", "N2", "E1", "N3", "Open Fronthaul U-plane", "F1-C"],
 "groups": [
   {"t": "AP／SCTP／IP",   "s": [{"a": 2}, {"a": 3}, {"a": 6}]},
   {"t": "GTP-U／UDP／IP", "s": [{"a": 4}, {"a": 0}]},
   {"t": "eCPRI／Ethernet", "s": [{"a": 1}, {"a": 5}]}
 ], "e": "……"}
```

- `items`：所有項目（含干擾項），不能重複。練習、模擬考和列印時項目都會打亂，照分組順序寫也不會洩漏答案。
- `groups`：每組有標題 `t` 和格子 `s`。每格的 `a` 是該放的項目在 `items` 裡的位置（從 0 開始）。
- 格子沒有標籤時，同一組裡順序不拘。
- 格子加上標籤 `l`，就變成逐格判分。適合「依序經過哪幾站」這類題目：

```json
"groups": [{"t": "由 UPF 往 UE 的順序", "s": [
  {"l": "第 1 站", "a": 3}, {"l": "第 2 站", "a": 5}, {"l": "第 3 站", "a": 0}
]}]
```

- 每個項目最多放進一格。沒放進任何格子的項目就是干擾項，題目要註明「有 N 個項目用不到」。

### 2.4 排序（order）

```json
{"n": 10, "type": "order", "q": "UE 從開機到可以上網，把下列程序排成正確的先後順序。",
 "items": ["RRC Setup：……", "Registration：……", "PDU Session Establishment：……", "使用者資料開始經 N3 傳送"],
 "e": "……"}
```

- `items` 照**正確順序**寫，至少 2 個，不能重複。
- 需要干擾項時，改用帶標籤的分類題。

### 2.5 配對（match）

```json
{"n": 13, "type": "match", "q": "把每個介面對到它使用的應用層協定。",
 "pairs": [["N2", "NGAP"], ["E1", "E1AP"], ["F1-C", "F1AP"], ["Xn-C", "XnAP"]],
 "e": "……"}
```

- `pairs`：至少 2 組 `[左, 右]`。左欄固定，右欄練習時會打亂。
- 左欄、右欄各自都不能重複，否則無法判定。

### 2.6 頁面內建的補充題（題號 1001 以上）

題號寫成 1000 + k（k 從 1 開始）的題目算補充題，題型和欄位跟題庫的題目完全一樣。用在題庫定稿之後才加的題目，讓題庫原本的題號和統計不受影響。

- 題庫地圖上不放在「題庫」區，而是依題型排進補充題區：單選、複選在「補充題：選擇題」，分類、排序、配對在「補充題：拖拉題」。
- 各區自己從 1 編號，依 k 的先後排，所以畫面上的號碼和 k 不同。例如 1001（單選）、1002（排序）、1003（複選）會顯示成補充選擇題第 1 題、補充拖拉題第 1 題、補充選擇題第 2 題。
- 有補充題時，練習設定會出現「題目來源」，可以選「只出題庫」或「只出補充題」。統計的「題庫」列只算 1 到 999 的題目。縮寫題（`abbr` 和頁面上新增的縮寫題）自成一類，統計有自己的一列，也不屬於這兩個來源，只在「全部來源」時出現（引擎版本 2026-10-29 起）。
- 題型篩選不分來源：補充題裡的分類、排序、配對和題庫的一樣，同時算在主要題型（`mainLabel`）和「拖拉題」。
- 使用者在頁面上自己新增的補充題，編號接在最大的 k 之後，和內建補充題排在同一區。
- 已經發佈的練習簿要再加內建補充題時，k 要接在頁面裡的補充題和帳號裡的補充題（作答紀錄的 `extras`）兩邊最大的號碼後面。k 如果比使用者已經新增的補充題小，畫面上的號碼會重排；作答紀錄綁在題號上，不受影響。

### 2.7 題幹區塊（blk）

題目本身有表格、一段引述的需求、log、程式碼或一張圖，而且圖表要夾在題目文字中間時，用 `blk`。題目文字 `q` 用 `{{0}}`、`{{1}}`……標出每個區塊的位置，`blk` 依序放這些區塊。五種題型都能用。

```json
{"n": 23, "q": "下表是 4 個狀態、5 個事件的狀態轉換表：\n{{0}}\n從 Requesting 開始，下列哪一組事件序列涵蓋最多有效轉換？",
 "blk": [{"t": "table", "hr": 1, "hc": 1, "cap": "Events",
          "rows": [["State", "Available", "NotAvailable"],
                   ["S1: Requesting", "S2", "S3"],
                   ["S2: Confirmed", "", ""]]}],
 "o": ["……"], "a": 1, "e": "……"}
```

| 類型 `t` | 欄位 | 說明 |
|---|---|---|
| `table` | `rows`、`hr`、`hc`、`cap` | `rows` 是每一列的文字陣列，每一列的格數要一樣，空白的格子寫 `""`。`hr`：最上面幾列是表頭（預設 0）。`hc`：每列最左邊幾格是列標題（預設 0）。`cap`：表格上方的小標題。 |
| `box` | `text` | 方框：一段引述的需求、user story、同事的說法。用 `\n` 換行。 |
| `pre` | `text` | 等寬字的程式碼或 log，空白和換行照原樣顯示，太寬時在區塊裡左右捲動。 |
| `img` | `img`、`alt`、`w` | 圖片代號（和 `img` 欄位一樣引用圖片區塊）、圖的文字說明、顯示寬度（px，手機上縮到畫面寬）。可以點一下放大。深色模式會反相，所以適合白底黑線的圖表，照片請改用題目附圖 `img`。 |
| `svg` | `svg`、`alt` | 直接寫在題庫裡的 SVG 原始碼，用 `currentColor` 畫線和字，深色模式會跟著變色。不能有 `script`、`on*` 屬性（例如 `onclick`）或 `javascript:`，有的話那一題是錯誤。 |

- `{{n}}` 前後的文字各自成段，`{{n}}` 單獨放一行最好讀。每個區塊在 `q` 裡剛好出現一次，`{{n}}` 的數字要對得上 `blk` 的長度，不然那一題是錯誤。
- 練習、模擬考、交卷後檢討、考前快速瀏覽、列印和成績頁的題目摘要都照位置排好。AI 解析的提示詞把表格（一列一行，格子用 ` | ` 分開）、方框和程式碼轉成文字放回原位，圖片寫成〔附圖：alt〕；`img` 區塊的圖接在題目附圖後面一起送給 AI，`svg` 不送，所以 `alt` 要寫出圖裡的重點。
- 什麼時候用 `blk`、什麼時候用題目附圖 `img`，見 `writing-guide.md`「題幹裡的表格和圖」。

### 2.8 逐選項解析（oe）

單選、複選題可以逐一說明每個選項為什麼對、為什麼錯：

```json
{"n": 422, "q": "……", "o": ["50%", "66.7%", "75%", "100%"], "a": 0,
 "e": "整體的說明：這題的判斷依據是什麼。",
 "oe": ["TC1 和 TC2 都落在 R1，TC3 落在 R3，只有 2 個不同規則，2/4 = 50%。",
        "這是把觀察到的兩種結果除以三種結果；題目要算的是四個規則的覆蓋率。",
        "把三次測試當成三個不同規則會多算。",
        "R2 和 R4 都還沒執行到。"]}
```

- `oe` 和 `o` 一樣長，**照 `o` 的原始順序寫**，不需要說明的選項寫 `""`。
- 作答時選項會打亂，頁面依畫面上的順序標字母、標出正確選項，所以 `oe` 裡**不要寫 A、B、C**，也不要寫「第幾個選項」；要提到別的選項時引用它的內容。
- 作答回饋、考前快速瀏覽、交卷後檢討、不可作答的題目和列印的複習講義都會列出來（列印時用印出來的字母）；AI 解析的提示詞也會帶上，用選項內容稱呼。
- `e` 仍然建議寫，講這題整體的判斷方法和容易卡住的地方；`oe` 只講各選項本身。

### 2.9 學習目標、認知層級和出處（lo、k、ref）

考試大綱有學習目標編號時可以標出來，三個都是文字、都可以省略：

```json
{"n": 433, "lo": "FL-5.1.5", "k": "K3", "ref": "Syllabus v4.0.1 §5.1.5", "q": "……"}
```

- 解析下方多一行：「學習目標 FL-5.1.5（K3），第 5 章 測試活動管理；出處 Syllabus v4.0.1 §5.1.5」。題庫有章節時接上這題的章名。
- 列印時題號後面寫成「E 卷第 33 題（FL-5.1.5，K3）」。
- AI 解析的提示詞會帶上學習目標、章節和出處。

## 3. abbr：縮寫題

學員看到縮寫，要寫出英文全名。判定時會忽略大小寫、標點、連字號、多餘空白、and／of／the 這類虛詞和字尾的複數 s。

練習時答錯或看答案後，答案下方會出現「遮住再打」，讓學員把全名打 3 次，判定規則和作答相同。所以 `alts` 要把常見的正確寫法列齊，不然學員打了合理的寫法也會被判錯。

```json
"abbr": [
  {"cat": "介面協定", "abbr": "GTP-U", "full": "GPRS Tunnelling Protocol User Plane",
   "alts": ["GPRS Tunneling Protocol User Plane"],
   "e": "封裝使用者資料的隧道協定，跑在 UDP 上……"}
]
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `abbr` | 是 | 縮寫，不能重複。 |
| `full` | 是 | 英文全名。 |
| `cat` | | 分類，練習時顯示。 |
| `alts` | | 其他也算對的寫法（拼法差異、常見變體），最多 10 個。 |
| `e` | 建議 | 說明：這個縮寫是什麼、用在哪裡。 |
| `ch` | | 這個縮寫屬於哪一章，和題目的用法相同，見第 6 節。 |
| `void` | | `true` 表示不可作答，和題目的用法相同，見第 8 節。 |
| `voidNote` | 有 `void` 時建議 | 這個縮寫題哪裡有問題，會顯示給作答的人看。 |

作答紀錄依**排列位置**記錄。新增加在最後，不要插入或刪除中間的項目；發佈後發現某個縮寫不該出，標成不可作答，不要刪。

## 4. groups：易混淆題組

把考相似概念、容易搞混的題目綁成一組。練習時同組連續出題，每題作答後附上這組的「分辨關鍵」。

```json
"groups": [
  {"name": "通道通了 vs 合作成功", "qs": [3, 5, 15],
   "key": "SCTP association 是通道，Setup 是應用層合作。控制面全部成功，也不代表使用者面的路徑是通的。"}
]
```

- `qs`：至少兩個存在的題號，可以跨題型。
- `key`：一兩句話講清楚怎麼分辨。

## 5. cases：情境題組

個案型教材常常一段情境就要出好幾題。把共用的情境文字（可以附圖）寫一次，底下掛好幾題；作答時情境一直顯示在題目上方，題目只寫這一題要問的事。

```json
"cases": [
  {"id": "pdu-setup", "title": "試驗場建立 PDU Session",
   "text": "手機已經完成 Registration，接著要建立 PDU Session……\n工程師在 CU-CP 上同時抓 N2、E1、F1-C 三個介面……",
   "img": ["lab-topo"],
   "qs": [16, 17, 18]}
]
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | 題組代號，規則和章節的 `id` 相同：0 以上的整數，或 1 到 20 個字的文字，不能重複。**發佈後不要改**，作答的人勾選和收起的題組是用 `id` 記住的。 |
| `title` | 是 | 題組名稱。作答畫面顯示成「情境：名稱（第 2／5 題）」。 |
| `text` | 是 | 情境文字，用 `\n` 分段，不用 Markdown。 |
| `img` | | 情境附圖的代號陣列，例如 `["seatmap"]`，和題目的 `img` 一樣引用圖片區塊。 |
| `qs` | 是 | 題號陣列，照出題順序排。 |

- 情境題組不是新題型。和易混淆題組一樣，它只是引用題號的外層結構：底下的題目維持原本的題型（單選、複選、分類、排序、配對）、題號和欄位，作答紀錄照樣綁在題號上。所以已經發佈的練習簿也能把現有題目包成情境題組，題號不動，作答紀錄不受影響。
- 一題最多屬於一個情境題組，但可以同時在易混淆題組裡。題號 1 到 9998（含 1001 以上的內建補充題）都可以放；縮寫題和使用者在頁面上新增的補充題不能放。
- 題目的 `q` 只寫這一題要問的事，背景寫在 `text`，不要在每題重複交代。什麼時候該用、怎麼避免同一組互相洩題，見 `writing-guide.md`。
- 題庫有章節時，同一組的題目最好在同一章。
- 沒有 `cases` 的練習簿，畫面和行為和沒有這個功能時完全一樣。

### 頁面怎麼處理

- **作答畫面**：情境顯示在題目上方，標示「情境：名稱（第 2／5 題）」，第幾題是在這一組可以作答的題目裡排第幾。同一組連續作答時情境區塊沿用、不重畫，圖片不閃動，區塊裡捲到哪裡也不變；情境太長時在區塊裡捲動。每一組都可以按「收起情境」，收起的狀態會記住、跟著帳號同步；還沒收起過的組一律先展開，所以換到新的一組時一定看得到情境。
- **練習**：「開始練習」多一個「情境題組整組出」（預設勾選，會記住，跟著帳號同步）。勾選、而且出題範圍是全部題目、還沒做過或已標記時，抽到題組裡的題目，就把同一組符合目前題型、題目來源、章節和情境題組勾選的題目，照 `qs` 順序接著出完。題數夠了就停，所以最後一組可能讓這回比設定的題數多幾題，開始按鈕上會寫「約 10 題」。不勾時每題獨立抽，一樣顯示情境。
- **錯題複習、弱點題、到期複習、考我一題、每日一題、易混淆題組**：一次出一題，題目上方一樣顯示所屬的情境。
- **模擬考**：以題組為單位抽題，同一組一起出、不拆開。放不下的題組先跳過，改抽單題或較小的題組補足；怎麼抽都湊不到剛好的題數時，用最接近的抽法。所以實際題數可能比設定的多或少幾題：題數欄下方的說明寫出這個規則，作答畫面和成績頁寫出實際題數，倒計時依實際題數計算。「照正式考試」時每一章各自照這個規則抽，情境題組整組算在它第一題所在的章節。
- **情境題組欄**：「開始練習」多一個「情境題組」欄，可以複選，不勾就是全部；有不屬於任何情境題組的題目時，多一個「不屬於情境題組的題目」可勾。勾選會記住，跟著帳號同步，套用在練習、模擬考、考前快速瀏覽和列印；每日一題和考我一題不分情境題組，兩者的說明都寫明這點。
- **題庫地圖**：情境題組的題號格底部有色條，題號相鄰的兩組用不同顏色。下方多一張「各情境題組的掌握情況」，列出每一組的題號、已作答和正確率；點名稱就只勾這一組。
- **成績頁**：有出到情境題組時，列出各情境題組答對幾題。
- **考前快速瀏覽、列印**：同一組的題目排在一起，中間不會插進別的題目。情境只出現一次：快速瀏覽在這一組的第一題顯示完整情境，後面幾題只標出是哪一組的第幾題，可以展開再看；列印在這一組的第一題前面印一次情境（含附圖），標出是第幾到第幾題共用。答案表不變。
- **AI 解析**：送給 AI 的提示詞包含情境名稱和文字。附圖先送情境附圖，再送題目附圖和選項圖片，一樣只送內嵌的 PNG、JPG、GIF、WebP。
- **不可作答**：不可作答的題目照常跳過，整組出時也不會被帶進來。一組扣掉不可作答的題目後一題都不剩，就不出現在任何地方。

### 檢查

- 頁面：題組本身格式有錯（`id` 重複或格式不對；缺 `title`、`text` 或 `qs`；`img` 不是代號陣列）時，那一組不出現，錯誤列在頁面最上方。`qs` 裡個別題號有問題時只提醒、略過那一題，那一題照樣出現，只是不屬於任何情境題組。`img` 的代號不在圖片區塊時只提醒，那張圖不顯示。
- `build.py` 把下列都當成錯誤：`id` 重複或格式不對；缺 `title`、`text`、`qs`；`qs` 裡的題號不存在、同一題出現在兩個情境題組、同一組裡題號重複；放了縮寫題或頁面上新增的補充題；`img` 用到不存在的圖片代號。
- `build.py` 另外提醒：題組只有一題（或扣掉不可作答的題目後只剩一題、一題都不剩）；同一組的題目分在兩個以上章節；情境文字提到「圖」卻沒有附圖；情境文字超過 800 字。題目或解析提到「圖」、而它所在的情境題組有附圖時，不再提醒沒有附圖。

## 6. chapters：章節

教材、原廠題庫或考試大綱本來就分章節（章、模組、Domain）時，加上章節清單，每題用 `ch` 標出屬於哪一章。作答的人就能只練某幾章，模擬考也能照正式考試各章的題數出題。教材沒有分章節就不要加，練習簿的畫面和沒有這個功能時完全一樣。

```json
"chapters": [
  {"id": 1, "name": "第 1 章 測試基礎", "sub": "Fundamentals of Testing", "exam": 8},
  {"id": 2, "name": "第 2 章 貫穿軟體開發生命週期的測試", "sub": "Testing Throughout the SDLC", "exam": 6},
  {"id": 3, "name": "第 3 章 靜態測試", "exam": 4}
],
"questions": [
  {"n": 1, "ch": 1, "q": "……", "o": ["……"], "a": 2, "e": "……"}
]
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | 章節代號：0 以上的整數，或 1 到 20 個字的文字（例如 `"M04"`、`"D2"`），不能重複。題目的 `ch` 寫這個值；`1` 和 `"1"` 視為同一章。 |
| `name` | 是 | 畫面上顯示的名稱。照教材的寫法連編號一起寫，例如「第 1 章 測試基礎」「Module 04 威脅情報資料蒐集」。 |
| `sub` | | 副標，例如原文章名。顯示在各章節表的章節名稱下方。 |
| `exam` | | 正式考試這一章出幾題。教材或考試大綱有寫才填，不要自己估。 |

- 題目和縮寫題都可以標 `ch`。沒有標的題目算「未標章節」；使用者在頁面上新增的補充題也算未標章節。
- `chapters` 的順序就是畫面上的順序。題號不用照章節排。
- 章節不影響作答紀錄。已經發佈的練習簿可以之後再加章節或改題目的 `ch`，作答紀錄都還在；但章節的 `id` 發佈後不要改，作答的人勾選的章節是用 `id` 記住的。

### 頁面怎麼處理

- 「開始練習」多一個「章節」欄，可以複選，不勾就是全部章節。有未標章節的題目時，多一個「未標章節」可以勾。勾選會記住，跟著帳號同步。
- 章節套用在開始練習的練習和模擬考、考前快速瀏覽和列印。**每日一題和考我一題不分章節**，一律從全部章節抽；兩者的說明和章節欄的說明都寫明這點。
- 題庫地圖下方多一張「各章節的掌握情況」：每章已作答幾題、累計正確率，有填 `exam` 時再加正式考試題數。點章節名稱就只勾這一章。
- 練習或模擬考出到兩個以上章節時，成績頁列出各章節答對幾題。
- 有章節填了 `exam` 時，模擬考的「題數」多一個「照正式考試」：從勾選的章節（不勾就是全部）各抽 `exam` 題。目前的題型和出題範圍裡某一章不夠時，那一章有幾題就出幾題，說明裡寫少了多少。沒填 `exam` 的章節和未標章節不會抽到。有情境題組時，每一章各自以題組為單位抽、不拆開，題組整組算在它第一題所在的章節，見第 5 節。

### 檢查

- `ch` 對不到任何一章：`build.py` 當成錯誤；頁面只在最上方提醒，那題算未標章節，不會消失。
- `build.py` 另外提醒：沒標章節的題目、沒有題目的章節、`exam` 比題庫裡這一章的題數（不算縮寫題）還多，以及只有部分章節填了 `exam`。

## 7. sets：卷別與整套模擬考

題庫是好幾份完整的考卷（例如官方範例試題 A 到 D 卷）時，加上卷別清單，每題用 `set` 標出屬於哪一卷。作答的人就能只練某一卷，也能照原卷順序考一整卷。題庫不是一卷一卷的就不要加，練習簿的畫面和沒有這個功能時完全一樣。

```json
"config": {
  "passLine": 65, "pace": 90, "fullMinutes": 60, "extraTime": 0.25,
  "setLabels": {"set": "官方範例題", "add": "官方附加題", "unoff": "原創練習題"},
  "fullNote": "標「內建」的 A 到 D 卷是官方範例試題；E 卷是另行編寫的原創練習題。"
},
"sets": [
  {"id": "A", "name": "A 卷"},
  {"id": "E", "name": "E 卷"}
],
"questions": [
  {"n": 23, "set": "A", "no": "23", "q": "……"},
  {"n": 44, "set": "A", "no": "A4", "add": true, "q": "……"},
  {"n": 433, "set": "E", "no": "33", "unoff": true, "q": "……"}
]
```

`sets` 的每一卷：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | 卷別代號，規則和章節的 `id` 相同：0 以上的整數，或 1 到 20 個字的文字，不能重複。**發佈後不要改**，整套模擬考上次的成績是用 `id` 記住的。 |
| `name` | 是 | 畫面上的名稱，例如「A 卷」。題號會寫成「A 卷第 23 題」，附加題寫成「A 卷附加題 A4」。 |

題目的欄位：

| 欄位 | 說明 |
|---|---|
| `set` | 這題屬於哪一卷，寫 `sets` 裡那一卷的 `id`。只有題庫的題目（1 到 999）能標；1001 以上的內建補充題不能。 |
| `no` | 卷內題號，文字或整數，最多 10 個字，例如 `"23"`、`"A4"`。題庫地圖的題號格和題號都用它；沒填時用 `n`。 |
| `add` | `true` 表示附加題：屬於這一卷，但不在整套模擬考裡（例如官方範例試題後面另外附的題目）。題庫地圖和卷別篩選另外列成「A 卷附加題」。 |
| `unoff` | `true` 表示原創題：不是取自官方或教材原本的題目，是另外編寫的。題目旁的來源標籤用 `setLabels.unoff`；有原創題時，題庫地圖和整套模擬考在卷名旁標「內建」或「原創」（整卷都是原創題的標「原創」）。 |

`add`、`unoff` 寫 `true`／`false`（也接受 `1`／`0`）。作答紀錄還是綁在題號 `n` 上，卷別和卷內題號只影響畫面，所以已經發佈的練習簿也能之後再加卷別。

config 裡和卷別有關的欄位：

| 欄位 | 說明 |
|---|---|
| `setLabels` | 題目旁的來源標籤：`set` 是有卷別的題目（預設「題庫」）、`add` 是附加題（預設「附加題」）、`unoff` 是原創題（預設「原創題」）。主頁標題下的題數也照這三種分開算。 |
| `fullMinutes` | 整套模擬考的時間（分鐘），每一卷都一樣。沒填時是這一卷的題數乘上 `pace` 秒。 |
| `extraTime` | 非母語加時的比例，見第 1 節。整套模擬考多一個加時後的考試時間。 |
| `fullNote` | 整套模擬考說明後面接的補充，例如哪幾卷是官方試題、哪幾卷是原創題。 |

### 頁面怎麼處理

- **題號**：有卷別的題目寫成「A 卷第 23 題」，旁邊的來源標籤是 `setLabels` 的說法。題庫地圖的題號格顯示卷內題號。
- **題庫地圖**：依卷別分組，每一卷一塊，有附加題時另外一塊「A 卷附加題」，沒有卷別的題庫題目放在最後的「其他題庫題目」。卷別的題號格排得比較緊密（電腦一列 20 格，手機一列 10 格），複選、拖拉這類小字標籤改成底線。
- **整套模擬考**：主頁多一區「整套模擬考」，每一卷一個按鈕，寫上次的成績和及不及格。按下就照題號順序考這一卷（附加題和不可作答的題目除外）：交卷後才看答案，一律倒數計時，及格線是 `passLine`，成績頁寫出「這回要答對 N 題」。題目照原卷順序，選項順序會打亂；遇到情境題組也照題號順序，不重排。有 `extraTime` 時可以選加時後的時間，選擇會記住。每一卷上次的成績和選的時間存在設定裡，跟著帳號同步。
- **卷別欄**：「開始練習」多一個「卷別」欄，單選，後面的數字是目前的題型、章節、情境題組和出題範圍裡、這一卷的題數。套用在練習、模擬考、考前快速瀏覽和列印；選了某一卷時，沒有卷別的題目、補充題和縮寫題不會出現。這個選擇和「題目來源」一樣不記住，重新整理後回到「全部」。**每日一題和考我一題不分卷別**，和章節、情境題組一樣，兩者的說明都寫明這點。
- **題數**：有整套模擬考時，「題數」的第三個按鈕從 50 題改成最常見的一卷題數（例如 40 題）。
- **列印**：說明裡寫出選的卷別；有 `printNotice` 時印在最後一行。
- 卷別、章節和情境題組可以同時用：三個條件都符合的題目才會出。

### 檢查

- `set` 對不到 `sets` 裡的任何一卷，或用在 1001 以上的題號：`build.py` 當成錯誤；頁面只在最上方提醒，那題當成沒有卷別，不會消失。
- `sets` 的 `id` 重複或格式不對、缺 `name`；`no` 不是 1 到 10 個字的文字或整數；`add`、`unoff` 不是 `true`／`false`／`1`／`0`；config 的 `setLabels`、`fullMinutes`、`extraTime` 格式不對：`build.py` 當成錯誤（頁面上卷別本身的格式錯誤也是錯誤，config 的格式不對只提醒、改用預設值）。
- `build.py` 另外提醒：沒有題目的卷、整卷都是附加題、同一卷裡卷內題號重複、沒有卷別的題庫題目、有 `no` 或 `add` 卻沒有 `set`。

## 8. 不可作答的題目

練習簿發出去之後，才發現某一題不該出，就把它標成「不可作答」：題目留在題庫裡，但不能作答、不計分。題目和縮寫題都能標，加兩個欄位：

| 欄位 | 說明 |
|---|---|
| `void` | `true` 表示不可作答。省略或 `false` 就是一般題目。只能寫 `true`／`false`，不加引號。 |
| `voidNote` | 這題哪裡有問題，會顯示給作答的人看。建議必填，沒寫時檢查會提醒。可以用 `\n` 分段。 |

```json
{"cat": "時間同步", "abbr": "JBOD", "full": "Just a Bunch Of Devices", "e": "……",
 "void": true,
 "voidNote": "JBOD 這個縮寫沒有出現在任何一份參考資料。ptp4l 手冊頁只有 boundary_clock_jbod 這個選項名稱，以及引號裡的「just a bunch of devices」，這題是出題時自行把兩者湊成縮寫，不符合「只根據教材出題」的原則。"}
```

題目原本的欄位（`q`、`o`、`a`、`e`、`items`、`pairs`、`full`、`alts`……）全部留著，格式檢查照常進行。不可作答只是多一個狀態，不是另一種題型；頁面還是要用這些欄位顯示原本的答案。

### 什麼時候用

- 題目考的不是教材裡的內容。例如縮寫題的縮寫根本沒有出現在教材裡，是出題時自己湊的。
- 題目本身有錯，而且改不成一題合理的題目。

只是答案標錯、選項或解析寫錯，改得好的題目直接修正就好，不用標。`voidNote` 要寫清楚哪裡有問題、依據是什麼，讓做過這題的人看得懂它為什麼被撤掉。

新出的題庫不該一開始就有不可作答的題目，這兩個欄位是給已經發佈的練習簿用的。

### 標了之後，頁面怎麼處理

- 題庫地圖上，這題的題號格或縮寫方塊變成灰色、虛線框、刪除線，圖例多一項「不可作答」。
- 點進去不能作答，直接顯示 `voidNote`、原本的答案和解析，不記錄作答。
- 練習、模擬考、考我一題、每日一題、錯題與到期複習、易混淆題組、考前快速瀏覽和列印都不會出到它。
- 不計入題數、已作答數和正確率。
- 易混淆組扣掉不可作答的題目後不到兩題時，那一組不會出現在練習裡，`build.py` 會提醒。
- 情境題組裡的不可作答題目照常跳過，整組出時也不會被帶進來；一組扣掉不可作答的題目後一題都不剩，就不出現，`build.py` 會提醒。

### 為什麼不要直接刪

- 作答紀錄綁在題號上。縮寫題的題號是照排列位置算的，從中間刪掉一筆，後面所有縮寫題的作答紀錄都會對到別的縮寫。
- 做過這題的人應該看得到「這題為什麼有問題」，而不是題目無聲無息地消失。

### 作答紀錄會保留

標成不可作答不會刪掉、也不會改動這題的作答紀錄、複習排程和標記，頁面只是不顯示、不計算、不抽到它。之後把 `void` 拿掉（或改成 `false`）重新產生，這題就恢復成一般題目，原本的狀態顏色和複習排程都會回來。

### 和爭議題（`flag`）的分別

| | 爭議題 `flag` | 不可作答 `void` |
|---|---|---|
| 意思 | 答案有討論空間 | 這題不該存在 |
| 作答 | 能作答，照常計分 | 不能作答，不計分 |
| 題庫地圖 | 紫色「!」和加粗外框 | 灰色、虛線框、刪除線 |

兩個可以同時標，畫面上以不可作答為準。

只有題庫裡的題目（題號 1 到 9998）和縮寫題能標。使用者在頁面上自己新增的補充題沒有這個欄位；那種題目不要了，在頁面上刪掉就好。

## 9. 圖片

圖片區塊是 `{"代號": "圖片"}`。題目用 `img`（題目附圖）、`eimg`（解析附圖）、`oimg`（選項圖片）和題幹區塊 `blk` 裡的 `img` 區塊引用代號，情境題組用 `img`（情境附圖）引用代號。值可以是：

- data URI：`"data:image/png;base64,..."`。圖片包在 HTML 裡，單一檔案就能分享。**放到 Claude artifact 時一定要用這種。**
- 相對路徑或網址：`"images/topo1.png"`。HTML 放在內部網站、圖片放在旁邊的資料夾時可以用，檔案比較小。

用 `scripts/build.py --images 資料夾` 時，檔名去掉副檔名就是代號，PNG／JPG 會自動轉成 WebP 縮小。

AI 解析會把情境附圖、題目附圖、題幹區塊的圖和選項圖片一起給 AI 看（先情境附圖，再題目附圖和題幹區塊的圖，最後依 `o` 的順序附選項圖片），但只限內嵌的 PNG、JPG、GIF、WebP；SVG 和外部檔案不會送，AI 只能靠情境、`alt` 和選項的文字推論。

### 選項圖片

- 只用在單選和複選題：`oimg` 和 `o` 一樣長，每格是代號或 `null`。用在其他題型、長度不同、或某一格不是代號也不是 `null`，頁面和 `build.py` 都當成錯誤，那一題不會出現。代號不在圖片區塊時，頁面只提醒、那張圖不顯示；`build.py` 和 `img` 一樣當成錯誤。
- **同一題的選項圖片要用同一個畫布寬度輸出。** 頁面依圖片的像素寬度縮放：電腦上通常照原寸顯示，手機上縮到選項的寬度。寬度不同的圖縮小的比例不同，圖裡的字看起來就大小不一。做法：畫布寬度取這一題最寬那張圖的寬度，其他圖內容靠左、右邊留白補到同寬。`build.py` 發現同一題的選項圖片寬度不同時會提醒。
- 不要另外加寬畫布：多出來的空白也會一起縮小。手機上選項大約只有 260px 寬，圖裡的字最好至少是畫布寬度的 1/20（例如 500px 寬的表用 25px 的字），縮小後才看得清楚。
- 寬和高都不要超過 1800px。`--images` 會把超過的圖等比例縮小，太高的圖會連寬度一起縮，就和同一題的其他圖不同寬了。
- 用 SVG 時，`<svg>` 要寫 `width`，同一題的 `width` 一樣。想讓 AI 解析看得到圖，就用 PNG。
- 圖裡不要畫 A、B、C 這類選項代號，選項會打亂。

### 舊版練習簿的 `[[fig:代號]]`

有些舊版練習簿在程式裡用 `const FIGS` 放 HTML 表格，題目或選項文字寫 `[[fig:代號]]`。新版引擎不支援這種寫法，會原樣顯示 `[[fig:…]]`。`build.py --extract` 遇到時會列出哪些題目要手動處理，`--check` 也會提醒。做法：題目文字裡的表格，改寫成題幹區塊 `blk` 的 `table`，把 `[[fig:…]]` 換成 `{{0}}`（見 2.7）；選項本身是表格時，把每個表格輸出成圖片（照上面的原則同寬輸出），改用 `oimg` 引用，文字裡的 `[[fig:…]]` 換成簡短說明。

## 10. 會讓頁面報錯的格式規則

頁面開啟時會檢查格式，有錯的題目不會出現在練習裡，錯誤列在頁面最上方。最常見的錯：

- JSON 語法：最後一個項目後面多了逗號、字串裡的雙引號沒有寫成 `\"`、用了全形引號。
- `a` 從 1 開始算。正確是從 0 開始。
- 題號 `n` 重複，或用了 1000。
- 分類題的同一個項目放進兩格。
- 配對題右欄有重複的字。
- `void` 寫成 `"true"`（加了引號），或 `voidNote` 不是文字。
- 章節的 `id` 重複、`exam` 不是 0 以上的整數。
- `oimg` 和 `o` 不一樣長（沒有圖的選項要寫 `null`，不能省略），或用在單選、複選以外的題型。
- 情境題組的 `id` 重複或格式不對，或缺了 `title`、`text`、`qs`：那一組不會出現。
- 同一題放進兩個情境題組、同一組裡題號重複，或把縮寫題、頁面上新增的補充題放進情境題組：頁面只提醒、略過那一題，但那一題就不在情境題組裡了。`build.py` 會當成錯誤。
- 有 `blk` 時，題目文字裡的 `{{0}}`、`{{1}}` 和 `blk` 的區塊數對不上（少了、多了或重複）；表格每一列的格數不一樣；`svg` 裡有 `script`、`on*` 屬性或 `javascript:`。
- `oe` 和 `o` 不一樣長，或用在單選、複選以外的題型。
- 卷別的 `id` 重複或缺 `name`；題目的 `no` 太長、`add`／`unoff` 寫成 `"true"`（加了引號）。
- 兩個區塊裡出現 `</script` 這幾個字（會讓瀏覽器提早結束區塊）。
