# 作答紀錄備份檔的格式

練習簿主頁最下方「備份作答紀錄」匯出的 JSON 檔（`<config.id>-progress-YYYYMMDD.json`）。用來備份、搬到另一台裝置，或交給別人分析作答情形。引擎版本 2026-10-20b 起才有這個功能。

所有時間都是 Unix 時間戳記（毫秒），只有 `exportedAt` 是 ISO 8601 的 UTC 時間。

「AI 解析」按鈕寫好的解析不在備份檔裡：它另外存在瀏覽器的 `<config.id>-ai-v1`，和帳號的 `<config.id>-ai-0`、`<config.id>-ai-1`……（每 100 題一份），照題號存成 `{"text": 解析, "t": 時間, "h": 題目指紋}`。`h` 是寫好當時的題目內容指紋（引擎版本 2026-10-29 起），題目改過之後對不上，畫面就標出這段解析可能過時。「清除所有進度」也不會清掉它。

## 最外層

| 欄位 | 內容 |
|---|---|
| `format` | 固定是 `"mock-exam-progress"`。 |
| `formatVersion` | 格式版本，目前是 `1`。練習簿讀不懂比自己新的版本，會拒絕匯入。 |
| `engine` | 匯出時的引擎版本，例如 `"2026-10-20b"`。 |
| `id`、`title` | 練習簿的 `config.id` 和 `config.title`。匯入時 `id` 不同會警告。 |
| `exportedAt` | 匯出的時間。 |
| `state` | 作答紀錄本身，和練習簿存在瀏覽器（`<config.id>-progress-v1`）和帳號裡的內容相同。 |

## state

| 欄位 | 內容 |
|---|---|
| `v` | 紀錄的結構版本，`1` 或 `2`，兩者的結構和題號編法相同。`2` 是 ISTQB CTFL 客製版把補充題、縮寫題換成下方的編號之後標的；引擎版本 2026-10-28b 起，本機、帳號和匯入的紀錄是 `2` 時照樣讀、不換號，寫回時保留 `2`。更早的引擎匯入 `2` 的備份會拒絕。 |
| `stats` | 每題的作答紀錄，key 是題號（見下方）。沒做過的題目不會有這一筆。 |
| `marks` | 標記：`{"題號": {"on": true 或 false, "t": 時間}}`。取消標記會留下 `on: false`。 |
| `prefs` | 設定：題型 `qtype`、作答方式 `recall`、計時 `timerMode` 和 `pace`、模擬考 `examMode` 和 `examTypes`、略過已熟練 `skipMastered`、統計列 `statRows`（`orig`、`extra`、`abbr`、`sum` 各是 `true`／`false`；`abbr` 是引擎版本 2026-10-29 起的縮寫題列）、每日一題 `daily`（今天換過一題時多 `sw`、`swk`、`swsub`）、換掉延後中的題目 `dailyHold`（`{"題號": 可以再出現在每日一題的那天}`，那天是當地日期從 1970-01-01 起算的天數；引擎版本 2026-10-23 起）、勾選的章節 `chapters`（章節 `id` 轉成文字的陣列，`""` 是「未標章節」，空陣列或沒有這個欄位就是全部章節；引擎版本 2026-10-24 起，只有題庫有 `chapters` 的練習簿會用到）、情境題組的三個設定（引擎版本 2026-10-28 起，只有題庫有 `cases` 的練習簿會用到）：整組出 `caseWhole`（`true`／`false`，沒有這個欄位就是開著）、收起的情境題組 `caseFold`（`{"題組 id": true}`，展開時拿掉那一筆）、勾選的情境題組 `cases`（題組 `id` 轉成文字的陣列，`""` 是「不屬於情境題組的題目」，空陣列或沒有這個欄位就是全部）、整套模擬考的兩個設定（引擎版本 2026-10-28b 起，只有題庫有 `sets` 的練習簿會用到）：選了加時後的時間 `fullExtra`（`true`／`false`；CTFL 客製版存的是選的分鐘數 `fullMin`，沒有 `fullExtra` 時照它判斷）、每一卷上次的成績 `fullRes`（`{"卷別 id": {"r": 答對題數, "n": 題數, "t": 時間, "x": 有加時時是 true}}`）。`t` 是最後修改時間。 |
| `extras` | 在頁面上新增的補充題（和從題目匯入收件匣併進來的題目），key 是補充題編號 k。刪掉的題目留下 `{"k": …, "del": true, "t": …}`。 |
| `groups` | 自訂的易混淆題組。目前只會從題目匯入收件匣併進來，頁面上沒有建立的介面。 |
| `resetAt` | 最後一次按「清除所有進度」的時間，`0` 表示沒有清除過。 |
| `session` | 還沒做完的那一回練習，沒有就是 `null`。以情境題組為單位抽題的那一回多一個 `want`：設定的題數，成績頁拿它和實際題數對照（引擎版本 2026-10-28 起）。整套模擬考那一回多 `full`（卷別 `id`）和 `fullX`（選了加時後的時間時是 `true`）（引擎版本 2026-10-28b 起）。 |
| `updatedAt` | 最後修改的時間。 |

### 題號

| 題號 | 是什麼 |
|---|---|
| 1 到 999 | 題庫的題目，和 `bank.json` 的 `n` 相同。 |
| 1001 到 9998 | 頁面內建的補充題，和 `bank.json` 的 `n` 相同。 |
| 10000 + k | 在頁面上新增的補充題，題目內容在 `extras` 裡。 |
| 20000 + j | 縮寫題，j 是它在 `abbr` 裡的位置，從 1 起算。 |

### stats 的每一筆

| 欄位 | 內容 |
|---|---|
| `c`、`w` | 累計答對、答錯的次數。 |
| `s` | 目前連續答對的次數，答錯歸 0。 |
| `last` | 最後一次的結果：`"c"` 答對、`"w"` 答錯。 |
| `h` | 最近五次的結果，由早到晚，例如 `"wcc"`。 |
| `p` | 最近五次的作答內容，和 `h` 一一對應：單選是選項在題庫裡的位置（從 0 起算），複選是位置的陣列，縮寫題是輸入的文字，排序和配對是排列（第 i 個位置放的是第幾個項目），分類題是每一格放的項目（`-1` 是空格）。沒記到時是 `null`。 |
| `t` | 最後一次作答的時間。 |
| `lv`、`due` | 間隔複習：等級 0 到 5（答錯歸 0，答對加 1）和下次到期的時間。間隔依序是 10 分鐘、1、3、7、14、30 天。 |
| `st` | 這一段連續答對從什麼時候開始，用來判斷熟練；答錯時拿掉。 |

### 畫面上的狀態怎麼來

- **未作答**：沒有這一筆，或 `c + w` 是 0。
- **答錯待複習**：`last` 是 `"w"`。
- **複習中**：答錯過（`w > 0`），但連續答對還不到 2 次（`s < 2`）。
- **已掌握**：其餘有作答的題目。
- **熟練**：已掌握，而且 `h` 是 `"ccccc"`、`lv` 至少 4、`t - st` 至少 7 天。

## 匯入時怎麼合併

- `stats`、`marks`、`extras`、`groups` 逐筆比較，保留 `t` 較新的那一筆。舊的備份不會蓋掉之後的作答。
- 比任一邊的 `resetAt` 早的作答紀錄和標記都不會留下：按過「清除所有進度」之後，清除前的紀錄（包括清除前存的備份）不會再匯入；備份裡的清除時間比這裡的作答晚時，這裡較早的紀錄也會被清掉，匯入前畫面會先警告。
- `prefs` 整包比較 `t`，取較新的。
- 正在做的練習不會被換掉。這裡沒有未完成的練習、而且備份來自同一份練習簿時，才接手備份裡的 `session`。
- 情境題組只是題目的外層結構，`stats` 的題號和格式不變。引擎版本 2026-10-28 之前匯出的備份可以直接匯入，題目的狀態不會變。`prefs` 是整包取較新的：備份的設定比較新時，因為舊備份裡沒有情境題組的設定，這三項會回到預設值（整組出開著、全部展開、不分題組）。
- 卷別、題幹區塊和逐選項解析都不影響 `stats` 的題號和格式（題號仍然是 `n`，不是卷內題號 `no`）。引擎版本 2026-10-28b 之前匯出的備份可以直接匯入，ISTQB CTFL 客製版匯出的（`v` 是 `2`，設定裡有 `fullMin` 和 `fullRes`）也一樣。備份的設定比較新、但裡面沒有整套模擬考的設定時，這兩項會回到預設值（標準時間、沒有上次的成績）。
- 也可以匯入沒有包外層的 `state`（例如從瀏覽器開發者工具直接複製出來的），但畫面會當成來源不明，要使用者確認。
